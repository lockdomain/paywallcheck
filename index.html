What it checks

Paid flags users can edit

Fields like is_paid, plan or credits that a logged-in user can change from the browser.

Rows other users can read

Tables where row level security is on, but a policy still lets one user see another user's data.

Payment events anyone can send

Webhook endpoints that grant access without checking that the event really came from Stripe.

How it works

  1. Prove the app is yoursAdd a DNS record or a file to your site. We never test apps you can't prove you own.
  2. Connect your deploysThe check runs after each deploy, so a change your AI made yesterday can't quietly reopen a hole.
  3. Fix with one pasteYou get a plain-language report and a prompt for Lovable, Cursor or Claude Code that fixes the issue.

A fix prompt, not a security lecture
